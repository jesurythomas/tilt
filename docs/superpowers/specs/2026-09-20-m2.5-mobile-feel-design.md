# Peril Point — Module 2.5 "Mobile feel": Design

Date: 2026-09-20
Status: Approved
Depends on: M2 (commit `0a15acf`)
Blocks: nothing — M3, M4, M5 and M7 may proceed in parallel, but all four
consume the input and HUD surfaces this module changes, so taking M2.5 first
avoids reworking them.
Parent spec: `docs/superpowers/specs/2026-09-20-peril-point-godot-port-design.md`
Conventions: `godot/CONVENTIONS.md`

---

## 1. Summary

M2 produced a first playable build. Device play on the Samsung Galaxy A55
(`SM_A556E`) found seven defects, all of them in how the game meets the player
rather than in the simulation:

1. No way to choose a control scheme.
2. Tilt steering is mistuned and drifts.
3. Touch steering shows no virtual joystick.
4. The score block is left-aligned and visually weak.
5. Ship, enemies and UI text are too small.
6. The arena border runs to the screen edge, under the device's own bezel.
7. The death screen is unstyled.

**Every one of these is a divergence from the TypeScript source.** That is the
reason this module has a spec of its own rather than being folded into M2 as a
round of fixes. `CONVENTIONS.md` §0 Law 4 forbids writing anything that is not
in the TypeScript or an explicit line of a spec. This document is that explicit
line, for each item, with its justification.

This module does **not** change the simulation. No enemy, weapon, particle,
grid or scoring behaviour is touched. Sections 5 and 6 below are specifically
designed so that `player_ship.gd`, `enemy_swarm.gd`, `weapon_system.gd`,
`particle_engine.gd`, `score_manager.gd` and `run_controller.gd` receive no
edits at all.

## 2. Divergence discipline

### 2.1 The `DIVERGENCE` tag

This module introduces a third comment tag alongside the existing `# PORT:` and
`# PORT-NOTE:`:

```gdscript
# DIVERGENCE(M2.5 §5.4): MAX_TILT_ANGLE is divided by a user sensitivity
# setting. At sensitivity 1.0 this reproduces the cited value exactly.
```

Rules, binding for this and every later module:

- Every deviation from ported behaviour carries one, citing the section of this
  document that authorises it.
- The tag is greppable. `grep -rn "DIVERGENCE" godot/src/` must list every
  deviation in the codebase, with no exceptions and nothing else.
- A `DIVERGENCE` tag is **not** a licence to invent numbers. Law 1 still holds:
  a divergent constant must be named, declared once, and justified — never
  scattered as a literal.

### 2.2 Where new code lives

Approach: **new concepts get new files outside the port mirror; changes to
existing ported behaviour happen in place, tagged.**

- New files with no TypeScript counterpart go in `godot/src/native/`. Each
  carries the header `## NO TS COUNTERPART — authorised by M2.5 spec §n`.
  Placing them outside `src/input/`, `src/sim/` and `src/ui/` keeps the
  one-file-to-one-file property of Law 3 legible: a reviewer diffing `src/`
  against `web/src/tilt-to-live/` sees a clean mapping, plus one directory that
  is explicitly not part of it.
- Edits to ported files are made in place with a `DIVERGENCE` tag. Moving
  ported logic into a wrapper to keep files "pristine" would be worse: it hides
  the deviation behind indirection, which is the failure mode Law 3 exists to
  prevent.

### 2.3 What stays untouched

`apply_orientation()` (`src/input/tilt_input.gd:136-171`) is the verbatim body
of `GyroscopeController.handleOrientation`. Its screen-angle branching and its
`MAX_TILT_ANGLE` / `DEADZONE_THRESHOLD` constants stay as written.

Consequently `calibrated_beta` and `calibrated_gamma` also stay — they are
`apply_orientation()`'s inputs. §5.2 **adds** a gravity-vector calibration used
by the device path; it does not replace them.

The seven `apply_orientation` assertions in `tests/test_tilt_input.gd`
(`test_neutral_orientation_inside_the_deadzone_yields_zero` through
`test_calibration_offsets_the_neutral_pose`) must pass **unchanged** after
§5.4's extraction. That is the evidence the refactor was behaviour-preserving,
and it is a required check.

Two tests in that file do change, deliberately and by authorisation of §5.3:

- `test_calibrate_without_sensor_data_falls_back_to_the_default`
  (`tests/test_tilt_input.gd:77-83`) asserts precisely the fallback that is
  Defect B. It is replaced by a test asserting the pending state.
- `test_calibration_round_trips_through_the_user_file`
  (`tests/test_tilt_input.gd:86-93`) gains gravity-vector coverage.

No other existing test in the repository changes behaviourally.

## 4. Control settings and scheme switching

Addresses defect 1.

### 4.1 `src/native/control_settings.gd`

New `RefCounted`, no TS counterpart.

| Member | Type | Default | Persisted |
|---|---|---|---|
| `scheme` | `Types.ControlScheme` | `GYRO` on mobile, `MOUSE` elsewhere | yes |
| `tilt_sensitivity` | `float` | `1.0` | yes |
| `tilt_smoothing` | `float` | see §5.4 | yes |

- `SETTINGS_PATH := "user://peril_point_settings.json"`
- `load_settings()` / `save_settings()`, mirroring the defensive JSON handling
  in `tilt_input.gd:229-253` — unparseable or wrongly-typed values fall back to
  defaults with a `Log.warn`, never a crash.
- Header carries `# TODO(M7): fold into meta/save_store.gd`.

Values are clamped on load. A settings file hand-edited to
`tilt_sensitivity: 900` must not produce an unplayable game.

### 4.2 Ownership and application

`GameRoot` constructs it alongside the other subsystems in `_ready()` and
applies `scheme` to `_router.control_scheme` before `_state.start()`.

Runtime switching goes through a single `GameRoot.set_control_scheme()`, which:

1. writes `_router.control_scheme` and persists,
2. runs the sensor transition already specified at
   `game_state_machine.gd:125-128` — entering `GYRO` calls
   `_tilt.start_listening()` then requests recalibration (§5.3); leaving it
   calls `_tilt.stop_listening()`,
3. calls `_router.clear_movement_keys()` and releases any active joystick
   touch, so a half-held input from the previous scheme cannot leak.

### 4.3 The picker

One scene, `src/ui/control_picker.tscn`, instanced in both surfaces:

- **TILT** → `Types.ControlScheme.GYRO`
- **TOUCH** → `Types.ControlScheme.MOUSE`
- **KEYBOARD** → `Types.ControlScheme.KEYBOARD`, hidden when
  `OS.has_feature("mobile")`

The active scheme is visually indicated. Buttons meet a minimum touch target of
48dp scaled by §7.2's `ui_scale`.

### 4.4 Pause overlay

A pause button anchors top-right inside the arena inset (§6). It calls
`GameStateMachine.toggle_pause()` — already ported from `TiltGame.ts:1619-1642`
— and shows an overlay containing the picker and a RESUME button.

No change to `GameRoot._physics_process`: its `match` already routes
`Types.GamePhase.PAUSED` to the `_: pass` arm, so the simulation freezes
correctly today. This is why `TiltGame.ts:1626`'s `TODO(M11): populate and show
the pause modal` is partially satisfied here; the TODO is narrowed rather than
removed, since M11 still owns the full modal with its settings and quit
options.

## 5. Tilt rework

Addresses defect 2. Device report: drifts when held still, axes feel wrong,
simultaneously too twitchy and requiring too much tilt.

### 5.1 Diagnosis

"Too twitchy" and "needs too much tilt" cannot both be true of a correctly
mapped axis pair. Reported together, they indicate **cross-coupling**: one
wrist movement bleeds into both output axes, so one overshoots while the other
under-responds. Three distinct defects are present.

**Defect A — the rotation transform is applied twice.**
`poll()` (`tilt_input.gd:188-201`) converts the gravity vector into scalar
`roll_deg` and `pitch_deg`, then reassembles synthetic `beta` and `gamma`
around `DEFAULT_CALIBRATED_BETA` and passes them to `apply_orientation()` —
which then applies its *own* screen-rotation branch (`tilt_input.gd:144-159`).
The landscape transform is applied once during the gravity decomposition and
again inside `apply_orientation()`. That is the cross-coupling.

**Defect B — calibration runs before the sensor has produced data.**
`game_root.gd:59` calls `_tilt.calibrate_current_position()` during `_ready()`.
At that moment `_has_received_data` is `false`, so `tilt_input.gd:113-115`
takes its else branch and falls back to `DEFAULT_CALIBRATED_BETA = 38.0` — a
neutral pose measured from a different grip. The saved file then makes this
persist across launches. This is the drift.

**Defect C — no sensitivity control.** `MAX_TILT_ANGLE = 24.0`
(`GyroscopeController.ts:172`) is one person's comfortable range of motion.

### 5.2 Replacement `poll()`

`poll()` is not ported code — its own header states there is no
`deviceorientation` event in Godot and that its axis basis was hand-derived
from five measured poses recorded in `HANDOFF.md`. It is replaced outright.

The new implementation works in vectors and never round-trips through angles:

1. Read `Input.get_gravity()`, falling back to `Input.get_accelerometer()`, as
   today. Normalise.
2. If calibration is pending (§5.3), capture this vector as
   `_calibrated_gravity` and return zero this frame.
3. Compute the deviation from the calibrated vector.
4. Project that deviation onto the screen's right and up axes in device space,
   derived once from `DisplayServer.screen_get_orientation()`. The rotation
   transform is applied exactly once, here.
5. Convert each projection to degrees and hand both to `_apply_angles()`.

`_calibrated_gravity: Vector3` is **added** to the persisted calibration
alongside the existing `beta` / `gamma` keys, which remain because
`apply_orientation()` still consumes them (§2.3). The device path reads the
gravity vector; the parity path reads beta/gamma. A calibration file written by
an M2 build carries no gravity key — that case loads as "calibration pending"
rather than crashing or silently using a stale pose.

### 5.3 Deferred calibration

`calibrate_current_position()` gains a pending state. When called with no
sensor data it sets `_calibration_pending = true` instead of falling back to a
hardcoded pose; `poll()` captures the real vector on the first valid sample.

Calibration is requested at three moments, all of which already exist as call
sites:

- `GameRoot._ready()` (`game_root.gd:59`)
- `GameRoot.restart_run()` (`game_root.gd:120`) — the "Play Again" path
- entering the `GYRO` scheme via `set_control_scheme()` (§4.2)

This satisfies the requirement that the game calibrates to however the player
is holding the phone at the moment they start or restart.

### 5.4 Sensitivity and smoothing

`tilt_input.gd:161-171` — the clamp, deadzone and re-normalisation — is
extracted verbatim into `_apply_angles(roll: float, pitch: float) -> void`,
called by both `apply_orientation()` and the new `poll()`. The extraction moves
no logic and changes no value.

Inside it, two divergences:

- **Sensitivity.** The divisor becomes `MAX_TILT_ANGLE / tilt_sensitivity`. At
  `tilt_sensitivity == 1.0` this is arithmetically identical to the cited
  constant, so the cited value remains the default behaviour and the deviation
  is a single named multiplier.
- **Smoothing.** `tilt_vector` is interpolated toward the computed target
  rather than snapped, damping the reported twitchiness. Smoothing `0.0`
  reproduces current behaviour exactly.

`DEADZONE_THRESHOLD = 0.07` is **unchanged**. With Defect B fixed, the neutral
pose is correct and the cited deadzone should suffice; widening it would mask a
calibration bug rather than fix it. Revisit only if drift survives §5.3 on
device.

Sensitivity and smoothing defaults are provisional and tuned on the A55 during
the device pass (§9). The spec fixes the mechanism; the numbers are measured.

## 6. Arena inset

Addresses defect 6. Requirement: shrink the playfield slightly so it clears the
device's bezel, cutout and gesture bar — not a visible letterbox.

### 6.1 Origin-offset model (D4)

Today `bounds` is `get_viewport_rect().size` and the sim treats `0..bounds` as
the playfield. That relationship is preserved: **`bounds` becomes the playfield
size, and a new `_arena_origin: Vector2` says where the playfield starts.**

The simulation is therefore unchanged. `player_ship.gd:249-259`'s wall clamp,
`run_controller.gd:62-68`'s orb spawn, the swarm's spawn edges and
`VectorGrid`'s dimensions are all already correct against a smaller `bounds`.

Four places learn about the origin:

| File | Change |
|---|---|
| `src/core/game_root.gd` | `resize_canvas()` computes `_arena_origin` and the reduced `_bounds` |
| `src/render/grid_layer.gd` | background across the full viewport; grid and perimeter offset by origin |
| `src/render/entity_layer.gd`, `src/render/effect_layer.gd` | `draw_set_transform(origin)` |
| `src/input/touch_input.gd`, `src/native/virtual_joystick.gd` | subtract origin from event positions |

`grid_layer.gd` painting its background across the **full** viewport while
drawing its perimeter at the playfield edge is what makes the inset read as a
frame rather than black bars.

### 6.2 Sizing

```
safe    = DisplayServer.get_display_safe_area()   # vs. the viewport rect
inset_y = clamp(max(safe_top, safe_bottom), MIN_INSET_Y, viewport.y * MAX_INSET_RATIO)
inset_x = clamp(max(safe_left, safe_right), MIN_INSET_X, viewport.x * MAX_INSET_RATIO)
```

Applied symmetrically, so the playfield stays centred and the arena does not
become lopsided when a cutout sits on one side only.

- `MIN_INSET_Y`, `MIN_INSET_X` — a small floor (order 12px and 8px) so the
  inset still exists on a device reporting no safe-area reduction.
- `MAX_INSET_RATIO` — a ceiling (order 4% per axis) so a device reporting an
  aggressive safe area cannot letterbox the game.

All three are provisional, declared once in `game_root.gd`, tagged, and
measured on the A55 during the device pass.

**Open verification, not an assumption:** `get_display_safe_area()` returns
screen pixels, and this project runs `content_scale_mode = disabled`. The two
spaces are expected to coincide, but that must be confirmed on device before
the numbers are trusted. If they do not coincide, the fallback is the fixed
floor alone.

## 7. HUD, scale and death screen

### 7.1 Score block (defect 4)

Replaces the left-aligned `HBoxContainer` at `scenes/main.tscn:47-81` with a
centred vertical block anchored top-centre inside the arena inset:

```
        1 2 , 4 8 0        <- score, large
         BEST 15,200       <- smaller, dimmer
            3x             <- gold, visible only above 1x
```

`hud_controller.gd`'s existing signal handlers are unchanged —
`_on_score_changed()` already sets all three labels and already gates the
multiplier on `multiplier > 1` (`hud_controller.gd:51-58`). This is a scene
layout change, not a controller change.

### 7.2 UI scaling (defect 5, text half — D6)

`main.tscn` hardcodes font sizes of 32/24/20px with no viewport response. The
parent spec's global constraints require all UI to be responsive and never
pinned to a base resolution, so this is a **bug fix** and carries no
`DIVERGENCE` tag.

`hud_controller.gd` derives a `ui_scale` from the viewport's minimum dimension
and applies it to font sizes and touch targets on ready and on `size_changed`.
Base sizes stay in the scene; the controller scales them.

### 7.3 Entity scale (defect 5, sim half — D5)

`arena_scale()` (`game_root.gd:128-132`) is cited verbatim from
`TiltGame.ts:2422-2431`. On the A55 — 1080×2340, landscape `min(w,h) = 1080` —
it evaluates `1080/680 = 1.588` and clamps to its `1.15` ceiling. There is no
headroom inside the formula, so no tuning of it can help.

A named `ENTITY_SCALE_BOOST` multiplier is applied to its result in
`resize_canvas()` before the value reaches `_player`, `_swarm` and `_weapons`.
The cited formula is untouched and the deviation is one constant. Provisional
starting value `1.25`, tuned on device.

**Recorded risk.** Larger entities inside a smaller playfield reduces
manoeuvring room twice over and makes the game harder. If the two fight each
other during tuning, the inset yields first: §6 is cosmetic, where §7.3 is the
defect the player actually reported.

### 7.4 Death screen (defect 7)

`GameOverPanel` (`scenes/main.tscn:82-149`) is restyled with `StyleBoxFlat`
drawing on the palette already declared in `grid_layer.gd:24-35` —
`BOUNDARY_COLOR`, the `#100c1e`/`#090712`/`#040308` background family — so the
panel belongs to the same neon-vector language as the arena.

Layout: title, new-record badge, stat rows (score, kills, time), the §4.3
control picker, and a full-width PLAY AGAIN. `hud_controller.gd`'s handlers
(`_on_run_ended`, `_on_restart_pressed`, `_on_restart_button_gui_input`) are
unchanged apart from node paths.

Built hand-styled so the module is never blocked on asset shopping.

### 7.5 Asset research (D8)

Runs alongside implementation, landing nothing in the repository until
approved.

Honest expectation: the Godot Asset Library is predominantly editor addons and
demo projects and has essentially nothing that drops in as a death screen. The
realistic candidates are a display font, a UI panel/button set, and possibly a
shader or particle effect, most likely from CC0 sources (Kenney, Google Fonts)
rather than the Asset Library itself.

Deliverable: 2–3 candidates, each with licence, file size and a note on fit
against the existing palette. Nothing is committed until a candidate is chosen.

## 8. Virtual joystick

Addresses defect 3.

### 8.1 `src/native/virtual_joystick.gd`

New `RefCounted`, no TS counterpart. Floating behaviour: the base appears
wherever the finger lands, the knob tracks the drag, both clear on release.

| Member | Purpose |
|---|---|
| `is_active: bool` | a finger is currently driving it |
| `base_position: Vector2` | playfield-local, set on touch-down |
| `knob_position: Vector2` | playfield-local, clamped to the base radius |
| `vector: Vector2` | direction with magnitude `0.0..1.0` |
| `on_touch()` / `on_drag()` / `on_release()` | fed from `GameRoot._unhandled_input` |

A single finger drives it, tracked by `InputEventScreenTouch.index`; a second
simultaneous touch is ignored rather than stealing control.

`touch_input.gd` is **not** replaced. It keeps its steer-toward-finger
behaviour, which is what `HYBRID` and desktop mouse still use. `GameRoot`
routes events to one or the other on `_router.control_scheme`.

Note `project.godot` sets `pointing/emulate_mouse_from_touch=true`, which
`touch_input.gd:22-25` documents as delivering both a screen event and a
synthesised mouse event for one drag. The joystick handles
`InputEventScreenTouch` and `InputEventScreenDrag` only, so the synthesised
mouse events cannot double-drive it.

### 8.2 Rendering

`src/render/joystick_layer.gd`, a `Node2D` appended **last** in `main.tscn` so
it draws above the entity and effect layers. Parent spec §5.4 fixes frame order
and §5.5 fixes render order; appending at the end adds a step without moving an
existing one, which is what those sections permit. Both sections gain a line
recording this layer.

It draws nothing while `is_active` is false.

### 8.3 Wiring (D3)

The joystick's `vector` is a normalised direction with magnitude — exactly the
shape of `TiltInput.tilt_vector`. When the touch scheme is active and the
joystick is engaged, `GameRoot._update()` passes `Types.ControlMode.GYRO` with
the joystick vector in the `gyro_vector` argument of `RunController.update()`.

`player_ship.gd` therefore needs **no new branch**: its existing gyro path
(`player_ship.gd:235`) handles it. No value is added to `Types.ControlMode`, a
cited port of `PlayerShip.ts:99`.

**The cost, stated plainly:** while a thumb is driving the ship, the internal
mode is named `GYRO`. This is a naming wart and is documented at both the call
site and in `types.gd`. It is accepted in exchange for leaving ported movement
code untouched. If M7's settings work gives `Types.ControlMode` a natural
reason to grow, revisit it then.

## 9. Testing

Existing GUT specs are extended rather than replaced, with the two deliberate
exceptions named in §2.3. That `tests/test_tilt_input.gd`'s seven
`apply_orientation` assertions pass **unchanged** is the evidence that §5.4's
extraction was behaviour-preserving, and is a required check, not an incidental
one.

The suite runs via `tools/run_tests.sh` — never `gut_cmdln.gd` directly. The
M2 baseline is 19 scripts, 99 tests, 425 asserts, all passing.

| Spec | Added coverage |
|---|---|
| `test_tilt_input.gd` | deferred calibration replacing the Defect B fallback test; vector-based projection; sensitivity at 1.0 reproducing cited output; smoothing at 0.0 reproducing unsmoothed output; legacy M2 calibration file loads as pending |
| `test_arena_scale.gd` | inset computation: floor, ceiling, symmetry, degenerate safe areas |
| `test_render_layers.gd` | origin transform applied to entity and effect layers |
| `test_hud_controller.gd` | font scaling across viewport sizes |
| `test_control_settings.gd` *(new)* | round-trip persistence; clamping; malformed and legacy-M2 files |
| `test_virtual_joystick.gd` *(new)* | vector magnitude and clamping; release; second-finger rejection |

Both new units are pure math on `RefCounted` objects and test headless.

**On-device acceptance on the A55** (`SM_A556E`), because none of the seven
defects were found by a test and none can be closed by one:

1. Each of TILT / TOUCH / KEYBOARD is selectable and survives an app restart.
2. Tilt: hold the phone at rest for 10s after starting — the ship does not
   drift. Tilt left, the ship goes left. Tilt magnitude and direction feel
   proportionate.
3. Play Again recalibrates to the pose held at that moment.
4. Joystick appears under the thumb, tracks, and clears on release.
5. Score block is centred and legible at arm's length; BEST sits below it.
6. Arena border clears the bezel and cutout on all four sides; no letterbox.
7. Entities read as larger without the game becoming unplayable.

Tuning values fixed during this pass — `tilt_sensitivity`, `tilt_smoothing`,
`ENTITY_SCALE_BOOST`, `MIN_INSET_*`, `MAX_INSET_RATIO` — are written back into
the source with a `DIVERGENCE` tag recording that they were measured, not
chosen.

## 11. Out of scope

- The title screen, entrance cinematic and full pause modal — M11.
- Consolidating the three `user://` JSON files into `meta/save_store.gd` — M7.
  This module adds a third and tags it accordingly.
- Any change to enemy, weapon, particle, grid or scoring behaviour.
- Gyro support on iOS — no macOS host is available (parent spec D1).
- Remapping keyboard keys.
- Audio for any new UI surface — M5.
