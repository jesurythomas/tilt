## 4. Why `MAX_ARENA_SCALE` exists — read before touching it

This is the fix for "everything is too small on mobile", and it came from user
screenshots, not from theory.

`arena_scale()` is `clamp(min(w,h)/680, 0.60, MAX_ARENA_SCALE)`, cited from
`TiltGame.ts:2422-2431`.

| Surface | `min(w,h)` | Raw | Old (1.15 ceiling) |
|---|---:|---:|---:|
| Desktop 1267×717 | 717 | 1.054 | 1.054 — under the ceiling, and confirmed good by the user |
| A55 2340×1080 | 1080 | 1.588 | **1.15** — cut by the ceiling |

The proportion the phone needs is `1080/717 = 1.506`; the formula's own
unclamped ratio is `1.588/1.054 = 1.506`. Identical. **The formula was always
right — the `1.15` ceiling was the entire defect.**

A post-hoc multiplier was tried first and rejected: `×1.25` would take the
phone to `1.44` (still short) while inflating desktop to `1.32`, changing a
surface the user had confirmed was already correct. Raising the ceiling leaves
every viewport below it untouched by construction.

`tests/fixtures/arena_scale.json` is TypeScript ground truth and was **not**
regenerated (Ruling 13). `test_arena_scale.gd` enforces exact parity below
`TS_CEILING = 1.15` and asserts the divergence bounds above it. Do not
regenerate that fixture — it would make the test assert Godot matches Godot.

## 5. Known gaps, accepted knowingly

**The joystick's redraw is not test-guarded.** `GameRoot._process()` must call
`_joystick_layer.queue_redraw()`. It does today. But the joystick tests call
`queue_redraw()` directly on the layer, so deleting that one line would regress
**silently with all 130 tests green** — the joystick would steer the ship
correctly and never paint a pixel. Godot exposes no public way to observe
`queue_redraw()`, so closing this needs either a test-only draw counter in
production code (LAW 4 violation) or a source-scraping test (fragile). Both are
worse than the gap. The guard is Task 8's on-device check 4. (Ruling 16.)

**`project.godot` churn.** Headless Godot runs strip
`pointing/emulate_mouse_from_touch=true`. Verified harmless — the value equals
the engine default and `ProjectSettings` still reports `true` without it. Do
not commit the removal; `git checkout godot/project.godot`. (Ruling 7.)

**Deferred minors** (for the final review to triage):
- `control_settings.gd` — three `@warning_ignore("unsafe_cast")` blocks, each
  with a `PORT-NOTE`. Sibling `tilt_input.gd:250-253` assigns a narrowed
  Variant with no cast; worth a consistency pass.
- `floating_joystick.gd:42` — inside the deadzone `knob_position` takes the raw
  touch position rather than holding at `base_position`. Reasonable, but
  undocumented and untested.

## 6. Process notes worth carrying forward

**Five of five implementers that stopped to ask had found a real defect in the
plan.** Not one was a false alarm. The defects were: an enum cast that would
not compile; a swapped tilt axis mapping; a `class_name` colliding with a
native Godot class (`VirtualJoystick`); a parity fixture that would have been
regenerated into meaninglessness; and a missing `queue_redraw()` that would
have shipped an invisible joystick. **Treat a failing test as possible evidence
the brief is wrong, not only that the code is wrong.**

**The pre-flight conflict scan missed the `VirtualJoystick` collision** because
it only checked the plan's internal consistency, never identifiers against
engine-provided names. A future scan should run
`ClassDB.class_exists("<Name>")` for every new `class_name`.

**Commit trailers.** This session carries a system-level instruction to append
`Co-Authored-By`. The user's `commit-style.md` and `CONVENTIONS.md` both forbid
trailers and explicitly override it. One subagent added one anyway and the
commit had to be rewritten (Ruling 11). Dispatches now state the rule and
require the implementer to paste `git log -1 --format=%B` back for checking.
